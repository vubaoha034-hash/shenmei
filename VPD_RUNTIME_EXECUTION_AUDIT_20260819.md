The repository already contains a deep distillation architecture capable of representing:

- photography decisions;
- graphic-design decisions;
- photo/design integration;
- measured evidence vs inference;
- causal quality hypotheses;
- style/content/brand/production binding;
- causal priority;

No repository artifact proves that those calls consumed a frozen VPD capsule, contrastive signature selection, compiler receipt, final prompt hash, runtime isolation policy, or post-render VPD gate.

Therefore the latest R4.2 images must be classified as:

`AD_HOC_HOST_GENERATION / NOT_FORMAL_VPD_EVIDENCE`

## 7. Required repair

Create a small **runtime execution gate**, not a new aesthetic architecture.

Every formal VPD generation experiment must produce, before rendering:

1. task ID and task type;
2. selected VPD route;
3. capsule/signature identity;
4. exact 4–8 high-leverage controls;
5. explicit variation freedoms;
6. max 3 generic-shortcut suppressions;
7. reference-runtime policy (`NONE`, `EXEMPLAR_BOUND`, or other declared mode);
8. compiler output;
9. final renderer payload/hash;
10. renderer/tool/model/settings identity where exposed.

After rendering it must record:

11. output identity;
12. technical gate;
13. human aesthetic gate status;
14. production-stage ownership (ImageGen vs Figma/layout vs real-photo edit).

If the host cannot prove these fields, the output is diagnostic only and cannot be called a formal VPD result.
