# 私人审美校准 V2.0

版本：`2.0.0`
状态：`MANDATORY`

AI 不能自动知道用户喜欢什么。私人审美必须来自用户明确确认的样本，不能从年龄、职业、地区或模型印象推断。

Adobe 不是审美锚点的存储依赖。

## 1. 稳定锚点来源

允许的稳定来源：

1. GitHub 仓库中的非敏感图片路径；
2. Figma 设计文件的具体 node URL；
3. 用户明确提供的长期稳定公共 URL；
4. 已验证可长期访问的文件库引用。

不允许作为正式锚点：

- 临时预签名 URL；
- 仅当前会话可用但未落库的本地路径；
- 已过期的 ChatGPT 临时文件链接；
- 只有文字描述、没有可检查图片的记录；
- AI 根据对话自行推断的喜欢或不喜欢。

## 2. 建议目录

```text
calibration/
├── anchors.json
├── RESTAURANT_BRAND_ANCHOR_POLICY_V1.md
├── approved/
├── neutral/
├── rejected/
└── references/
```

Git 不保存空目录；上传图片或建立 Figma 锚点后再记录。

## 3. 每个锚点必须记录

- `id`；
- `category`；
- `source_type`：`github_path` / `figma_node` / `stable_url`；
- `source`；
- `label`：`approved` / `neutral` / `rejected` / `reference`；
- 用户明确理由；
- 评分或区间（可选）；
- `confirmed_at`；
- `active`；
- 可见设计特征；
- 禁止误学的表面元素。

## 4. 品牌作品集锚点

餐饮品牌项目应分别准备：

- 顶级行业参考：`reference`；
- 用户明确喜欢：`approved`；
- 觉得一般：`neutral`；
- 明确失败：`rejected`。

顶级行业参考不自动等于私人喜欢。

对参考品牌必须同时记录：

- 允许学习：章节结构、留白、主图/细节/应用层级、版式节奏、材料和空间统一；
- 禁止复制：品牌名、Logo、口号、字体、页面壳、绿色山野表面组合、水印、署名、二维码和商业外观。

## 5. 最低数量

同类别：

- 少于 3 个有效锚点：`personal_fit = null`；
- 3–7 个：只能低到中等置信度；
- 8 个以上，且至少 2 个 approved、2 个 neutral、2 个 rejected：可正式计入；
- 推荐首次校准 12 张：4 喜欢、4 一般、4 不喜欢。

锚点不足不阻止公共专业评分，但禁止伪造私人匹配分数。

## 6. 对比流程

每次三页验证和十页审计必须：

1. 新方案匿名为 A/B/C；
2. 与至少一个 reference/approved 和一个 rejected 做成对比较；
3. 说明更接近谁，以及可见原因；
4. 分离专业标准、参考图接近度和私人偏好；
5. 锚点不足时保持 `personal_fit = null`；
6. 不因用户刚夸过一张图自动提高相似作品分数。

## 7. 锚点录入

只有用户明确表达：

- “这张很喜欢”；
- “这张一般”；
- “这张不喜欢”；
- “把这张作为参考”；

才允许新增或更新锚点。

在稳定图片尚未写入 GitHub 或 Figma 前，可以记录 `pending_anchor`，但：

- `active` 必须为 `false`；
- 不得参与正式 `personal_fit`；
- 必须注明缺少稳定视觉来源。

## 8. 版本与失效

- 修改评分标准必须提升 `rubric_version`；
- 旧结果不得静默重算；
- 用户新反馈与旧锚点冲突时，优先使用日期更新、理由更具体的记录；
- 失效锚点设置 `active: false`，不得删除历史原因。
