# 刘先生 VPD 图片生成

> 版本：正式操作文档 V1.0（2026-10-12）
> 性质：高级感 P／视觉审美操作系统的图片生成与完整设计工作流程。
> 本文件用于复用**现有**视觉蒸馏、来源血统、真人验收和 Figma 生产机制；不是第二个任务锁，也不意味着创建了新 Skill 或自动化程序已经上线。

## 0．唯一目标和三条原则

**目标**：从用户认可的真实优秀参考图片中提取有效的视觉机制，制作新的优质摄影、插画或设计作品；需要完整海报时，将通过审核的主视觉与可编辑文字合成，交付真实可查看的成品，而不是只交付提示词、测试报告或工程 PASS。

1. **参考不等于成品**：网上参考图片、我们生成的图片、用户认可的范围、失败候选与可商用终稿必须明确分开。
2. **先保护已取得的质量**：局部正确就保护局部，只改被证明不足的维度。不因“可能更好”重复抽样，不让失败退化覆盖当前最好图。
3. **图片质量高于工程复杂度**：深度分析可以完整，最终传给 Image 的指令应具体、可成像、主次清楚。技术正确不能冒充审美优秀。

## 2．定义本轮的唯一交付和范围

先明确以下六项：

| 问题 | 应有答案 |
|---|---|
| 目标 | 纯摄影 / 插画 / 字标 / 完整海报 / 局部修图 / A-B 对照 / 只读审核 / 仅归档 |
| 内容 | 新作品题材、主体、事实文案、使用场景、实际画幅 |
| 真参考 | 实际可读取的原始图片、来源、哈希、角色及使用权状态 |
| 冻结部分 | 哪张照片、哪个字标或哪段构图已获认可，不得重生或重做 |
| 预算 | 是否允许生成、最多几张、是否允许 Figma 写入、是否允许额外收费 |
| 验收 | 技术要求是什么，用户应实际看哪张图才能判定质量 |

**一轮只改一个明确维度**。图文合成任务不得擅自重新生成摄影；单纯图片生成任务不要顺带重写已经通过的字标；只读/归档任务不出新图。

## 3．实际参考图的身份与血统

先看到**真实像素**、解析实际 MIME、宽高、原始字节和 SHA-256。按角色登记：

- **REFERENCE**：用户提供或网上找到的优秀参考，摄影者/时间/许可不明时标 UNKNOWN，不能当成我们生成的作品。
- **CANDIDATE**：明确由本轮生成器实际返回的原始 PNG/JPEG/WebP，带来源与生成身份。
- **SCOPED_APPROVED**：用户只认可摄影、色彩、文字或其他一部分，须记录准确范围。
- **REJECTED / SUPERSEDED**：失败图或后来纠正过的评价，保留证据但不当现行真值。
- **GOLDEN / FINAL**：必须经过对应完整作品真人批准，不因一个技术检查或相对胜出而自动晋升。

每条血统应能逆向找到：真实参考哈希 → 蒸馏计划 → 提示词原文 → 生成会话/请求 → 原图 SHA-256 → 人审记录 → 后续 Figma 画框/导出。

特别注意：**X/Y 是文件身份，不是下载先后顺序。** 人审的对象必须锁定原文件名和 SHA-256。需要纠正时追加新的优先结论并使旧学习样本失效，不删除历史。

参考仅用于学习构图/光影/材料/语言；不要照搬第三方具体地形、照片或品牌商业外观。商业发布需另查权利边界，不能自动认定可商用。

## 4．视觉蒸馏：先理解画面，再决定生成变量

遵守 [视觉蒸馏编译器 V2](../VISUAL_DISTILLATION_COMPILER_CONTRACT_V2.md) 和 [审美 Skill 设计宪章](../AESTHETIC_SKILL_DESIGN_CHARTER.md)。

1. 分类：摄影主导（PHOTO_LED）、文字主导（TYPE_LED）、插画、材料印刷或图文混合。
2. 摄影拆解：主体尺度与机位、透视景深、前中远景/遮挡、明暗、光源柔硬、色相与饱和度分布、肌理及后期痕迹。
3. 设计拆解：第一视觉中心、留白和信息密度、标题形体、文本层级、图与字如何争让空间、材质与叙事。
4. 把稳定视觉机制与可变内容分离。保留“看起来属于同一审美语言”的因果关系；放开主体局部、地形轮廓等可创新部分。
5. **提取约 5—8 个真正会影响像素的高杠杆变量并排序**。判断必须有实际图像依据；推测镜头参数、拍摄地、摄影师、作者意图等，未核实时不能写成事实。

例如《地图以外》的重要关系不是泛泛的“美丽山路”，而是大面积亮色天空、淡桃灰远山、乳白云海遮挡、左下细窄山路与极小车、漫射光和低反差。生成新作时应创造新的地形，不描摹第三方照片的精确轮廓。

蒸馏可以深入，但蒸馏报告**不是要原封不动交给模型的提示词**。

## 5．生成提示词：信息充分，不靠字数、术语或禁令堆砌

由上一步把视觉机制编译成真正可成像的提示词：

1. 说清任务类型、主体、画幅、整体叙事和视觉锚点。
2. 选择对构图、光线、材料、主体尺度有决定作用的关键机制，优先 2—8 个，不能为凑数量重复写。
3. 只保留确实需要的反向限制。自动化候选编译器目前定义**最多 4 项避项**，只是该模块内部的边界，不是审美评分。
4. 把内容事实、品牌名和文字正确性放在适合的独立层处理；照片任务默认无烘焙标题。
5. 保存**最终实际发出的完整提示词**，而不是只保存写作草稿或一句“电影感、高级感”。

**必须保留的纠错：**2026-10-11 用户先按下载先后错认 X/Y，后明确纠正为 **Y 更好、X 有 AI 味**。X 属直接参考路线 A（提示词较短）；Y 属参考图+V2 机制路线 B（提示词较详细）。在这一组中 B 的相对质量较好，但只有一组，且最终纠错发生于已揭盲之后，不能宣称“长提示词普遍更好”或“V2 已经获得严格因果验证”。

证据：[A/B 冻结原文](../evidence/vpd/dituyiwai_photo_20261011/V2_STAGE1_AB_INPUTS_FROZEN.json)、[Y 优先的用户纠错](../evidence/vpd/dituyiwai_photo_20261011/V2_AB_HUMAN_CORRECTION_Y_PREFERRED_20261011.json)。

**写作习惯**：最终提示词要紧凑、准确、有视觉主次、没有冲突；可以保留真正有用的多项 V2 机制，不可机械压成最短字数，也不可把全部工程检查表塞给 Image。

## 6．真正调用 Image：必须接收对应参考原图

- 在 ChatGPT Image 路线，给该次生成**实际附上唯一正确的参考图**与本次提示词，核对发送后的附件身份、会话、输出数量。不可以“助手之前看过参考”代替真正的当前模型输入。
- Image 工具可能不公开内部参考绑定清单。记录**可观察的附件、提示词、输出、时间与限制**；不凭缺少内核回执断言参考完全没有生效，也不凭“长得像”伪称有完整绑定证据。
- 独立 OpenAI API 是另一条收费通道，和 ChatGPT 会员内的 Images 不等同。尚无明确付费授权时不能自行调用。现有 [自动化扩展 V1 候选](../plugins/visual-aesthetic-workflow/automation-v1/README.md) 有代码级的参考二进制输入、私有存储、状态机和成本签名审批设计，但**尚未部署到现有 Site**，不等于已具备端到端无人值守能力。
- 不因一次失败就去换 Adobe、重建 Site 或 Figma、增加新插件；优先在已连接且可靠的当前工具链内解决真实失败原因。

默认本轮只生成约定的**一张**。上传失败或归档失败不能自动成为重新生图的理由；先核对原有输出是否已存在。

## 7．受控实验与 A/B（仅在真的需要验证方法时执行）

A/B 不是所有创作的默认工序。需要验证一种蒸馏机制是否有收益时才开展：

1. 冻结同一原始参考、任务目标、画幅与两路实际提示词。
2. 若实验要求独立上下文，两路分别在不含对方结果和旧失败图的干净上下文执行。每路仅生成授权数量，不隐藏变体、不临时改词。
3. 输出保存为 X/Y，对应身份和 SHA-256 随原始文件存档。**先匿名评价实际作品，再依据文件哈希揭盲**，不以下载顺序或缩略图次序推测名称。
4. 先问“每张是否独立达到可用质量”，再问“哪张相对更好”；未过绝对质量不能凭相对胜出直接进入商业母版。
5. 随机性、输入绑定、模型设置和样本量不可控时，如实标注。用户纠错后保留旧原话与新结论的有效优先级。

## 8．一生成就保存：原始字节，不是屏幕截图

生成后立刻保存到**可实际读回**的现有 Drive、个人 ChatGPT 文件资料库或其它受控位置：

- 原始 PNG/JPEG/WebP 字节、真实 MIME、像素宽高、SHA-256、存储 ID / URL。
- 参考图来源 SHA、生成的真实提示词、生成会话或提供者请求记录、图像身份、实际生成次数。
- 如有编辑或裁切，记录为**另一个衍生版本**，原件不得被覆盖。
- 画幅要求严格 9:16 时，以 **16 × 实际宽度 = 9 × 实际高度** 核对；941×1672 只能称“近似 9:16”，不能算严格 PASS。
- 只在完成真正上传、回读与哈希核验后宣称保存成功。图库标题、回执声明、临时下载链接或网页截图都不能单独证明原始像素安全存档。

原件找不到、文件校验冲突、接口限权时标注 **BLOCKED / UNKNOWN**，不能重新生成一张冒充原件。

## 9．审核必须分离“能用”和“真正好看”

| 审核层级 | 应当核对 | 不允许的推论 |
| --- | --- | --- |
| 硬技术 | 参考身份、正确文字、实际比例、可读字节、原始像素、图层、导出哈希 | 通过不能证明审美优秀 |
| 视觉冷审 | AI 味、结构可信、光影材料、构图/负形、信息层级、缩略图与全图观看体验 | AI PASS 不能代替真人 |
| 真人审美 | 局部认可范围、绝对质量、相对偏好、是否能进入正式设计、是否批准终稿 | 相对胜出不自动等于商业定稿 |

审美失败时，明确是构图、质感、文字还是图文关系。**已通过的维度继续保护，只修失败维度。** 若没有实质改变失败原因的修复策略，就停止重复生成，不靠随机重抽形成“进度”。

## 10．锁定优秀图片，择一进入局部修复或完整合成

一旦用户确认“这一张已经很不错”，就保护其原始 PNG 和来源哈希：

- 若摄影已经够好，**优先检验完整设计**，不能为“可能更好”直接推翻它。
- 若仅局部雾气、纹理或主体逻辑不足，可在新候选中做有界修改，并保留原版与真实对照；退步可回滚。
- 若摄影已经通过但海报一般，优先检查文字尺度、可读性、图文竞争和留白关系，不强制重生成摄影。
- 只有用户批准相应**完整作品**才可晋升 FINAL/GOLDEN。不能拿一个摄影评分覆盖整张海报审批。

## 11．需要完整海报时才接入现有 Figma

复用**既有** Figma 项目与已通过的文字母版：

1. 原始摄影作为独立 IMAGE fill，不用一张扁平全海报截图冒充设计源。
2. 已批准中文字标/辅助信息使用原生 TEXT 或 VECTOR；克隆母版，不去修改已认可源节点。矢量是可编辑轮廓，不等于可以直接输入另一串文字。
3. 先看整张图的空间叙事，特别是字标、主体、小车或产品、留白与阅读顺序。只做一个完整候选，不在拍照/文字/配色之间无限乱切。
4. 用 Figma 真正的节点导出 PNG，核实画幅、图层和源原件，并独立比较原摄影与背景层保真。截图仅用于视觉观察，不能冒充原生导出原件或独立像素审计。
5. 向用户交一张**可见完整作品**及准确 Figma 节点，等待最终审美验收；未得到明确认可就不能发布或晋升。

现有工作流插件版本有 v0.5.0 图片合成合同，但其子任务登记可能被文件引用权限阻断。必须区分：**Figma 画面建好了**与**插件登记/独立审计/最终人审全都完成了**，不允许后者由前者自动推出。

## 12．证据闭环、学习和失败停止

每轮只需保留并关联四项已有类型的证据：**冻结输入、真实输出、真人反馈与纠错、学习结论**。继续复用 [持续学习规则](../rules/CONTINUAL_LEARNING_TRIGGER_RULE.md) 和现有 skill-refiner，不另造一套平行学习系统。

- **来源不明 / 原像素不可见**：停止宣称已学习参考。
- **实际模型输入缺少该参考**：不能把旁观阅读包装成参考式生图。
- **图片本身明显回退**：保留一次失败样本，回滚到保护版，不无界生成。
- **下载 X/Y 或图片身份错配**：用确定文件名、SHA-256 纠错，旧主观记录撤回当前有效性。
- **原生文件或审计缺失**：准确披露未完成，不把“有截图”当“正式交付”。
- **审美只在一个案例获胜**：作为局部证据，不直接修改全球 Skill。
- **任务锁/提交并发冲突**：先读最新并协调，不覆盖、不重做已完成成果。
- **需要额外收费**：先报费用或预算，用户明确批准后才执行。

跨案例证明 Skill 真正有用，需要换内容、换画幅和另外明显不同的参考风格做实际对照；只有多次**真人完整作品质量**支持，才考虑修改核心方法。
