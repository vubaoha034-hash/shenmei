# R26｜“云间”两字整体构图改写与否决机制｜2026-10-28

**裁决：原生Figma可编辑字形通过；“强行跨字共用顶横”失败。C保留识字但无确凿高级感，暂不晋升设计Skill。**

本轮针对刘先生此前的“只是换一种字体／毫无设计感”提出的新门槛：必须真正根据设计师观察到的**不同字密度失衡→尝试整体结构重组→重绘曲线→认读与审美回退**构建可复验新作品，而不是拿到相似书写字PNG或机械小幅变形。

## 证据来源与引用边界
选读张家佳本人2024年公开的 [《上座》餐饮商业字体标志设计过程](https://www.behance.net/gallery/196038613/_)，作者先诊断“上”疏、“座”密导致原排版不均，再尝试整组上下组合，随后实际重新设计手写曲线。其原始案例已在 [R12作者真实阶段图证据](../R12_VERIFIED_REAL_ARTIST_LETTERING_STAGES_AND_NEW_DECISIONS_20261027.json) 中建立来源血统。本次**不复制作者实际笔画轮廓或原图**，只把“密度诊断和整词拓扑决策”作为假设。

## 真正执行了什么

研究词 **「云间」**，其中云字疏朗、间字有包围结构。所有字形贝塞尔路径从空白手工编写，再真实导入Figma可编辑**VECTOR**层，不调用字体文件、不把AI图像自动描成矢量。两字均有正确结构，但并不等于有专业设计感。

### 核查
- Figma实际回读，A/B/C分别是12/11/12条 `VECTOR`，全部TEXT=0、IMAGE填充=0。
- B不只是改变字距，确实把原本两条笔画重新作者化为一条跨字路径。
- B在1400宽和240宽Figma截图都能看出贯穿整组的长横，但过度合并使云与间之间的形态边界受损；**判设计失败，不因共笔成功就晋升**。
- C采用视觉审查后预先冻结的一次回退；相对A仅改变 `云/首横`，其余11条Figma原生字形路径保持不变。C版依然较普通，**没有验证出比A显著更有设计感**。
- C的云横右端 x≈717，与间左竖墨迹边界 x≈728 相距**11个1600px画布像素**。缩放到240px画面时只剩约1.65px，若缩放到96px约0.66px，因而不能单凭大图判断小尺寸识字安全。
- 未获得独立人类无标签识别/审美投票。不能宣称专业字标、通用造型规则成功。

### 初稿语法错误不能抹掉
第一次SVG `间/日右竖` 中存在缺失贝塞尔控制点的无效C指令，导致Figma截图出现黑色巨大三角形。已经通过真实截图定位、在GitHub保留旧坏提交后修正，两个坏画框 `5:3`／`5:18` 在Figma中隐藏留档，正确A/B重新导入。不把语法修复冒充设计审美提升。详细路径源和原始Git Blob见下方台账。

## 下一步方向

**拒绝继续调“云间”的横笔宽度／长度。** 此次实验反而确证了一个重要的失败条件：两字强行连接会造成认字边界损失；避免共笔后作品又容易变普通。

之后应该回到真实设计师的阶段图，筛选具有可判断的**大轮廓变化**的作品，把语义、疏密、字势、识别的关系前置；在下一组不同结构的汉字上做有强烈设计选择的不同方案，而不是根据出现的向量数量统计“创新”。每次必须先做实际视觉评审、后进Figma；没有可见专业提升就停止，不将大量实验数据伪装为用户想要的专业设计能力。
