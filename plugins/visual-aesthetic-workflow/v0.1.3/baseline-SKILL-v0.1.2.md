name: visual-aesthetic-workflow
description: Read bound native GitHub state, prepare compact native-task or new user-request reference drafts, and collect artwork-bound human feedback. Requires separate image, Drive, Figma and independent pixel-review tools for production.
---

This is an experimental thin workflow wrapper, version 0.1.2. The authoritative repository is `vubaoha034-hash/shenmei`, branch `visual-program-distillation-v2-photography-design-20260814`. Its current native lock, checkpoint, adapter, charter, freezes and review carrier control the native task. This plugin does not create a task registry or replace production skills.

1. Call `get_current_workflow`. Use its actual latest commit and bound current entry; stop if native hashes, mirrors or mainline verification fail. Historical actions in the entry do not override `next_required_action`.
2. For the existing native task, retrieve the bound reference and current delivered artwork original bytes with connected Drive tools, recompute SHA256 and view pixels. Its typography-only scope, paused photography and source protection remain unchanged. For a new user-uploaded reference, use the actual attachment, Drive ID or URL in this request, retrieve its original bytes and view its pixels. Until those checks occur, its SHA can be unknown and its visuals are unverified. A plugin response or image URL does not supply pixel evidence.
3. Call `compile_transfer_plan` with the expected commit. `reference_scope:"native_task"` is the default and requires the exact bound native `reference_sha256`. For a new user reference, select `reference_scope:"user_request"` and supply bounded `reference_source` plus explicit `new_copy`; omit `reference_sha256` when unknown, or supply a canonical 64-hex caller hash that remains unverified until actual byte retrieval. This mode returns a request draft with `NOT_PERFORMED` verification and preserved `native_context`; it never rebinds the native reference. Its seven axes wait for this new reference's actual pixels, without inheriting native color, geometry or dimensions. Both modes use canvas, attention geometry, image anchor, material treatment, typography behavior, color logic and variation axis. Keep correctness separate from taste and reuse mature tools without rewriting upstream generation rules.
4. A draft does not grant quota. The actual execution carrier checks applicable scope and existing user authorization before production; authorization already covering the request remains usable, so do not demand repeated approval solely because `execution_authorized:false` appears in this draft. Use the actual image tool within that scope and connected Figma tools when editable source is part of delivery. Record actual calls, failures, source identities and exposed settings; a draft is not generated artwork or an accepted result.
5. Send actual reference and newly created artwork original pixels through the existing independent review carrier without creator history or human verdicts. For `user_request`, its packet contains only this request's reference, exact new copy and newly created artwork; exclude `native_context`, old artwork, old feedback, scores and verdicts. Preserve actual image-byte transport, model, runtime and isolation evidence. The plugin cannot instantiate an independent reviewer. If the route or pixels are unavailable, stop at `NEEDS_INDEPENDENT_PIXEL_REVIEW`; self-review and code tests cannot promote the work. AI review never replaces Liu's acceptance.
6. Repair only within applicable existing authorization and actual observed evidence. Save original artwork and editable source to authorized destinations and verify readbacks. For the native task, only the existing Root writer updates and publishes the same native state; when its next action is human review, do not start another native formal version. A user-request draft leaves that lock, checkpoint, adapter, ledger and next action intact.
7. For an explicit human rating of the current native delivery, call the published `save_human_feedback` tool with expected commit, exact delivered artwork SHA, a stable idempotency key, `APPROVE`/`REJECT`/`COMMENT`, and the user's comment. Its binding remains the native delivered artwork; a new request draft does not change that binding. Require `persisted:true` and its durable receipt, then verify it with `get_human_feedback`. The core-only `prepare_human_feedback` validates an intake but does not save it and is not a published workflow tool. Root reconciles this append-only **non-authoritative intake** with the native authority. Neither a feedback record nor an AI score may automatically change mainline, AI verdict or human `PENDING`.

Recognized and rejected outcomes remain scoped evidence. One rating defaults to observation; do not blindly append visual rules or claim universal transfer, improved efficiency or training. This wrapper initiates no training, scheduled runs or paid compute. Capability and adapter details are in [README.md](README.md).

Runtime source for this candidate is v0.1.2/core.mjs and worker.mjs. Original 0.1.0 and 0.1.1 cores are retained as baselines. The native delivery can name WORKER_CURRENT_REUSE.md or S7_FINAL_REUSE.md; both require matching native projections and exact pinned entry SHA. The published surface remains four tools; feedback persistence remains native-artwork-bound and non-authoritative D1 intake. Root records this version's actual publication and hosted verification in ../REQUEST_REFERENCE_RUNTIME.json. Older release files and bound native entry prose describe their historical versions; they do not establish 0.1.2 deployment or connection status. The implementation worker stops at local tests and build.
